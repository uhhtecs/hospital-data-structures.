Design Memo: Hospital Data Structures

A binary tree is appropriate for the doctor reporting structure because it represents relationships between supervisors and their direct reports. Each DoctorNode stores a doctor's name and links to two possible reports. This makes the structure easy to organize and update. The insert method searches for the parent and checks whether the requested position is available before adding a new doctor.

Preorder, inorder, and postorder traversals visit nodes in different sequences. Preorder visits the supervisor before the reports, which can be useful when creating a report that introduces a manager before their team. Inorder visits the left subtree, the current node, and then the right subtree. This is especially useful in a binary search tree because it can display values in sorted order. Postorder visits both subtrees before the current node, which can help process lower-level teams before their supervisor or remove a tree safely.

A min-heap is useful for emergency intake because it keeps the patient with the lowest urgency number at the root. Since 1 represents the most urgent patient, the system can quickly identify who should be next without sorting the entire queue. The insert method uses heapify_up, while remove_min uses heapify_down to maintain the heap structure. Insertion and removal typically take O(log n) time, while peek takes O(1) time. Although this system demonstrates how emergency queues work, actual hospital treatment decisions must still be made by qualified medical staff using approved triage procedures.
